# Аудит DevOps Stend v1

Дата базового аудита: 2026-09-21.

## Инвентаризация

На момент создания v2 в репозитории обнаружено:

- 664 файла;
- 41 Markdown-инструкция в `docs/`;
- 44 YAML/YML-файла в `YAML/`;
- 10 docker-compose файлов;
- 560 изображений;
- единственная исходная ветка до начала v2 — `master`.

v1 остаётся учебным legacy-слоем и не изменяется в рамках первого этапа v2.

## Критические и высокоприоритетные находки

### 1. Секреты и пароли в Git

В документации и конфигурациях встречаются literal credentials: пароли БД, Harbor, Keycloak/PG, Patroni и OIDC client secret.

В v2 запрещаем хранить реальные секреты в Git. Для Manual-трека допускаются только явно фиктивные значения. Для Automation-трека планируются SOPS/age или External Secrets/Vault.

### 2. Небезопасные TLS-настройки

Обнаружены примеры отключения проверки TLS, включая OpenShift Console и OpenSearch-инструкцию.

В v2 такие варианты должны:
- либо быть удалены;
- либо явно отмечаться как LAB ONLY;
- либо заменяться корректной CA-chain конфигурацией.

### 3. Redis без пароля

В текущем compose присутствует `ALLOW_EMPTY_PASSWORD=yes`.

В v2 сервисы по умолчанию не должны запускаться с отключённой аутентификацией, кроме специально обозначенных лабораторных упражнений.

### 4. Широкие Kubernetes-права

Найдены:
- `cluster-admin`;
- RBAC с wildcard `resources: ["*"]` и `verbs: ["*"]`;
- privileged containers;
- hostPath.

Это не обязательно ошибка для системных компонентов/лаборатории, но каждый такой случай в v2 должен иметь объяснение и минимально необходимые права.

### 5. Устаревшие Kubernetes API

В DEX-манифестах используется `extensions/v1beta1`.

В v2 новые манифесты создаются только на поддерживаемых API; legacy-файлы v1 не переписываем до отдельной миграции.

## Структурные проблемы v1

### Jekyll layout

В репозитории каталог называется:

```text
 _layouts/
```

с ведущим пробелом. Стандартный каталог Jekyll — `_layouts/`.

### Абсолютные URL в layout

В layout используются пути вида:

```text
/assets/css/style.css
/index.html
/roadmap.html
```

Для project GitHub Pages это потенциально ведёт в корень домена вместо `/DevOps_Stend/`. В v2 будем использовать `relative_url` / `site.baseurl`.

### Ссылки roadmap

`roadmap.md` ссылается на HTML-файлы без префикса `docs/`, тогда как фактические инструкции находятся в `docs/`.

### Пути к изображениям

Большинство инструкций используют Windows-style ссылки вида:

```text
..\images\\img_....png
```

В v2 пути должны быть POSIX/URL-compatible.

### Неполная навигация

`index.md` и `index_list.md` описывают основной маршрут 01–31, но в `docs/` присутствуют дополнительные инструкции 50–59.

### Дубли

Подтверждены как минимум пары с практически одинаковым содержимым:

- 06 / 52 — BIND DNS;
- 08 / 50 — Wildcard certificate.

При миграции сначала определяем canonical-версию, затем оставляем ссылки/redirect/reference на старый номер.

## Жёсткая привязка к лабораторному окружению

Во многих документах и YAML используются:
- домен `kubeadm.ru`;
- адреса сети `20.20.20.x`;
- конкретные hostnames;
- конкретные registry endpoints.

Для Manual-трека это может оставаться как пример стенда. Для Automation-трека всё окружение переводится в переменные.

## Версионность

В v1 зафиксированы конкретные старые версии/поколения компонентов, например Ubuntu 20.04, GitLab 14.4, Ceph 15 Octopus и OpenShift Console 4.12.

v2 не должен слепо заменять версии на "latest". Нужна матрица совместимости и pinning проверенных версий.

## Что НЕ делаем сейчас

- не удаляем старые документы;
- не меняем номера 01–59;
- не исправляем массово картинки;
- не меняем текущий GitHub Pages;
- не удаляем legacy YAML;
- не ротируем/переписываем значения прямо в v1 в рамках структурного коммита.

Сначала строим v2 рядом и создаём проверяемую карту перехода.
